# Re:代码生活

React + Vite 个人记录网站。Supabase 提供账号、数据库和私有图片存储，Netlify 发布前端。

## 本次实现

- 新增淡米白、柔粉和浅黄的亮色模式，首次访问默认亮色。首页导航和各功能页顶部可切换亮色/深色，当前设备记住选择并同步到其他标签页；表单、弹窗、Markdown 和代码高亮一起切换。
- 邮箱注册、验证邮件重发、忘记密码及邮件回调后的密码重置。所有人可注册，笔记写入需要作者发放的随机邀请码。
- 网站作者可生成 7 天或 30 天内可兑换的单次邀请码，复制后自行发送；可查看邀请状态、撤销尚未兑换的邀请。兑换后开通该账号自己的笔记空间，记录默认私密。
- 网站作者和所有已验证邮箱、已兑换邀请码的用户都能公开自己的笔记；在单条记录的管理页确认公开，访客无需登录即可阅读标题、标签、Markdown 正文和封面。
- 首页和“练习展示”汇总所有受邀作者主动公开的笔记，标注来源昵称与“网站作者 / 受邀作者”身份，提供公开搜索和标签筛选。“我的记录”、编辑、回收站、备份继续按登录账号隔离。
- “我的账号”可以设置 1 到 30 字的公开昵称，修改后所有公开笔记同步显示新昵称。未设置时提供稳定的默认作者名称，不自动使用账号邮箱；作者身份由数据库确定，修改昵称不会授予网站管理权限。
- 每条公开练习有独立分享链接，支持复制、取消公开；移入回收站自动取消公开，恢复后保持私密。
- 首页字体由 25,575,676 字节的完整 TTF 改为 13,820 字节的 WOFF2 子集；完整原文件保留在 `resources/fonts/`，不进入网站发布目录。
- 账号页显示当前邮箱，支持仅退出当前设备；登录后返回原页面，会话变化同步到其他标签页，退出时保留本机文字草稿。
- 数据备份页可导出 JSON，或导出包含封面的 ZIP；可选择包含回收站，按云端分页读取，不受列表已加载条数限制。
- Markdown 写作与预览，支持标题、列表、表格、任务列表、链接、图片和代码高亮；正文与备份组件按需加载。
- 首页记录框可滚动浏览，每批读取 12 条，接近底部时自动加载更多；记录列表、搜索、管理、回收站和封面清理各有独立页面。
- 详情页用于阅读，通过“管理记录”进入编辑、删除或恢复操作；搜索条件随返回链接保留。
- 左侧正方形封面、右侧标题和标签的可滚动记录卡片。
- 按标题搜索、按标签筛选；每批读取 12 条，使用创建时间和记录编号作为分页游标。
- 新增、编辑、回收站、恢复和确认后彻底删除。
- 保存携带固定操作编号，响应丢失后可重试，刷新后也可恢复待确认请求。
- 编辑检查版本，另一台设备修改后不会静默覆盖。
- JPEG/PNG/WebP 封面更换和移除；限制原图 5 MB，最长边压缩到 1600 像素。
- 只有记录保存成功后才清理旧封面；失败进入本机清理队列，列表可重试。
- 自己阅读私密记录时，图片使用一小时签名链接，页面打开期间约 50 分钟刷新一次。访客封面通过受权限检查的下载接口读取，不使用公开存储桶。
- 新增和编辑的文字草稿按账号隔离、在本机保存，支持恢复和丢弃，离开前提示。
- 草稿不跨设备同步。未上传的本地图片不会保存到草稿，需要重新选择。

## 首次启用这次更新（必须先执行云端升级）

本地源码修改不会自动更新 Supabase 数据库。

1. 在 Supabase SQL Editor 执行 `supabase/migrations/20261015_records_workflow.sql` 的完整内容。
2. SQL 在一个事务中执行，允许重复运行，保留已有记录和图片，增加版本、更新时间和回收站字段。
3. 升级后网页写操作统一通过 `mutate_record`，旧网页的直接新增/编辑将失效。请在空闲时升级，并紧接着发布新版前端。
4. 本地验证登录、保存、编辑、筛选、分页、回收站与封面，然后再推送、部署。
5. 在手机和电脑用同一账号测试，在不同账号之间验证不能访问彼此的记录。

升级脚本限制为只读表 + 用户专用写入函数，仍须在真实项目中确认账号隔离。后台 SQL Editor 使用管理员权限，不能用其“能读到所有行”来判断网页的 RLS 是否失败。

### 启用公开练习

1. 已完成上述升级后，在 Supabase SQL Editor 完整执行 `supabase/migrations/20261016_public_showcase.sql`，再发布新版前端。仅推送 GitHub 不会执行数据库脚本。
2. 脚本增加 `is_public` 字段和限定的公开读取接口，现有记录保持私密。脚本可以重复运行；重跑不会清除已明确设置的公开状态。
3. `record-covers` 必须是 Private 桶。脚本发现 Public 桶会停止，避免私密图片可以绕过权限直接下载。
4. 网站仅有一位作者。脚本从已有记录的唯一所属账号确定作者；没有记录时使用唯一的 Auth 账号。若存在多个候选，会停止并要求在脚本的 `author_email text := ''` 中填写作者的登录邮箱，再完整运行。网页不能自行更改作者身份。
5. 新版上线后，登录作者账号，进入“我的记录 → 一条记录 → 管理记录 → 公开展示”，阅读确认内容后点击“确认公开”。可复制公开链接，或点击“查看公开页面”检查展示效果。
6. 使用无痕窗口验证公开列表、正文和封面；私密记录和回收站记录不会展示。点击“取消公开”后，再次打开或刷新分享链接，应显示不可用。移入回收站也会撤回，恢复后需要另行确认公开。
7. 公开后的后续编辑直接更新公开内容；页面会显示提示。取消公开只阻止新的授权读取，不能收回已经被他人浏览、下载或保存的内容。

公开目录使用 `/?view=showcase`，分享详情使用 `/?show=记录编号`。原有 `/?record=记录编号` 链接会优先供作者阅读自己的记录，访客只能读取其中已公开的记录。

数据库升级按日期顺序执行。以下旧章节说明各阶段首次升级；已完成前面升级的项目，只运行尚未执行的新脚本。`20261018_member_publication.sql` 会增加公开接口的来源字段，不要在它之后单独重跑旧公开脚本。

可以运行 `node scripts/check-public-cloud.mjs` 做匿名只读检查。输出仅包含状态、错误码和最多一条结果的计数，不打印记录内容或密钥；它不能替代真实账号和图片服务的完整验证。

### 启用注册、邮件和邀请制笔记

先完成前两次升级，再完整执行 `supabase/migrations/20261017_invitation_auth.sql`，然后发布新版前端。已确定的网站作者自动保留笔记权限，其他账号需要验证邮箱并兑换邀请码。旧记录保留，账号仍能读取和备份自己的旧记录；没有邀请权限时不能新增或修改笔记。

访问规则：

| 身份 | 阅读公开练习 | 注册/登录 | 创建和编辑笔记 | 公开自己的笔记 | 生成邀请码 |
| --- | --- | --- | --- | --- | --- |
| 访客 | 可以 | 可以注册 | 不可以 | 不可以 | 不可以 |
| 未受邀的注册账号 | 可以 | 可以 | 不可以 | 不可以 | 不可以 |
| 已验证邮箱的受邀账号 | 可以 | 可以 | 可以 | 可以 | 不可以 |
| 网站作者 | 可以 | 可以 | 保留权限 | 可以 | 可以 |

使用流程：

- 新用户：登录页选择“注册账号” → 打开验证邮件 → “我的账号 / 开通笔记”兑换邀请码 → “我的记录”新增笔记。
- 作者：“我的账号 → 邀请管理”，选择 7 天或 30 天，生成并复制邀请码，自行发送给受邀人。有效期限制兑换时间，兑换成功后笔记权限不随邀请码到期而消失。
- 邀请码只可由一个账号兑换；已使用、已撤销或已过期的码不可再兑换。重复兑换不会消耗另一个邀请码。尚未兑换的邀请可撤销；本版不提供撤销已开通账号权限的入口。
- 原始邀请码只在本次生成成功的页面显示，数据库仅存 SHA-256。离开页面或刷新后不能找回原码；丢失时撤销该邀请并重新生成。网络失败时在当前页面点击“重试本次生成”，沿用同一个编号和随机码，不重复新增邀请。
- 邀请列表每批 20 条，支持加载更早的邀请。邀请码连续验证失败 5 次后，该账号在当前 15 分钟窗口内停止尝试。
- 忘记密码：登录页选择“忘记密码” → 输入邮箱 → 打开重置邮件 → 输入并确认新密码。普通用户不能通过该流程更改别人的密码。

Supabase 后台还需要以下设置，SQL 和 Git 推送不会代替它们：

1. Authentication 的注册设置允许新用户注册；Email 提供商开启确认邮箱。不要关闭邮箱确认来绕过发信配置。
2. URL Configuration 中 Site URL 设置为 `https://bright-gumdrop-41575b.netlify.app`，Redirect URLs 加入以下两个完整地址：

   ```text
   https://bright-gumdrop-41575b.netlify.app/?view=auth-confirm
   https://bright-gumdrop-41575b.netlify.app/?view=reset-password
   ```

   本地测试可另加入 `http://localhost:5173/?view=auth-confirm` 和 `http://localhost:5173/?view=reset-password`；使用其他端口时必须与实际地址一致。

3. 在 Authentication 的邮件设置中启用自定义 SMTP，填写发信服务给出的 Host、Port、Username、Password，以及允许使用的 Sender email。SMTP 密码只保存在 Supabase 后台，不写入源码、Netlify 的 `VITE_` 变量或聊天。默认 Supabase 邮件服务只向项目团队邮箱发信，不能据此认为所有新用户都能收到邮件。
4. 邮件模板可保持默认 `{{ .ConfirmationURL }}`。若自定义模板使用重定向地址，应使用 `{{ .RedirectTo }}`，确保密码重置仍返回密码页；不要把全部邮件固定重定向到首页。仅在已有合法模板中替换文案，不把 HTML 中的用户输入直接拼接成链接。
5. 用作者之外的真实邮箱完成一次注册和验证，确认兑换前打不开编辑器；作者生成邀请码后，用该账号兑换并写一条笔记；第三个账号不能使用同一码。再实际测试忘记密码邮件、过期链接和手机打开链接。

没有发信域名时，小范围验证可以先接入已有 QQ 邮箱的 SMTP：在 QQ 邮箱设置的“账号与安全 → 安全设置”开启服务并生成授权码；Host 为 `smtp.qq.com`，Port 为 `465`，Username 和 Sender email 为同一完整 QQ 邮箱，Password 为授权码。它是否允许 Supabase 所在服务器连接、具体投递速度和额度，需要真实发信验证；不把个人邮箱视为批量发信保证。后续用户量增加时可换成经过域名认证的事务邮件服务，前端无需改动。

依据：[Supabase 邮件与 SMTP 限制](https://supabase.com/docs/guides/auth/auth-smtp)、[邮箱密码与找回流程](https://supabase.com/docs/guides/auth/passwords)、[QQ 邮箱授权码说明](https://help.mail.qq.com/detail/106/985)、[腾讯官方 SMTP 配置示例](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。

`node scripts/check-invitation-cloud.mjs` 检查新接口是否存在、匿名是否无法读取成员和邀请表，以及公开的注册/邮箱确认配置；它不会注册账号、创建邀请或发送邮件。SMTP 与真实投递必须人工确认。数据库触发器约束写入函数，Storage 另加笔记权限规则，不能只靠隐藏按钮来实现邀请制。

### 启用受邀作者公开笔记和来源昵称

1. 已执行前面三份升级的项目，在 Supabase SQL Editor 完整运行 `supabase/migrations/20261018_member_publication.sql`，然后发布前端。脚本可重复运行，保留所有记录、邀请码、成员、昵称和已有公开状态；不会自动公开私密笔记。
2. 网站作者和已验证邮箱的受邀账号进入“我的账号 → 笔记来源昵称”设置公开昵称。未设置时网站作者显示“网站作者”，受邀账号显示固定的“笔记作者-…”；系统不从邮箱或可编辑的登录元数据生成作者身份。
3. 进入“我的记录 → 一条记录 → 管理记录 → 公开展示 → 确认公开”。笔记进入首页和公开列表，访客可打开独立分享链接；列表和详情都标明来源昵称与网站作者/受邀作者身份。
4. 每个账号只可公开、取消公开和修改自己的笔记。网站作者不会因此获得其他人的私密记录读取或代发布权限；普通注册账号仍需兑换邀请码。
5. 取消公开或移入回收站后，新的公开正文、标签和封面读取均停止；恢复后保持私密。昵称更新只影响来源展示，不改动笔记版本、内容或公开状态。
6. 使用真实受邀账号完成一次公开、无痕窗口阅读、取消公开和封面读取验证。运行 `node scripts/check-member-publication-cloud.mjs` 可匿名检查公开接口来源字段与昵称权限边界；不会发布记录、修改昵称或发送邮件。

新增的昵称表只允许受控函数读写。公开接口返回昵称和数据库确定的身份，不提供账号邮箱、登录元数据、内部权限或记录版本。不同账号可以选择相同昵称，身份标记不随昵称改变。

### 每日抽签与发布天数

1. 在 `20261018_member_publication.sql` 之后完整执行 `supabase/migrations/20261019_learning_garden.sql`，建立签到和发布历史。可重复执行，不修改任何笔记的正文或公开状态。
2. 学习花园已移除。发布新版前端后执行 `supabase/migrations/20261020_remove_learning_garden.sql`，停用花园专用的标签汇总接口。此清理可重复执行，保留发布历史、签到数据与标题所用接口；历史迁移按文件顺序执行。
3. 点击右侧竖排标题抽取今日签，同时完成签到。已验证邮箱的注册用户都可签到，不需要邀请码；写作和公开笔记仍然需要受邀权限。每天同一账号只保存一支随机签，重新打开、重试、换设备都读取同一结果。抽签用于学习鼓励，不作预测。
4. 标题数字是累计发布天数：登录用户看自己的，访客看站长的。以数据库 UTC+8（Asia/Taipei）自然日为准，一天内首次公开至少一篇新笔记就加 1，多篇仍只加 1。签到不增加发布天数；修改旧文、取消后重新公开不增加。发布过的天数不因删除、取消公开或中断几天而减少。
5. 升级从已有成功公开操作的记录恢复首次发布日期，不把笔记的创建时间当作公开时间。没有公开操作记录的手工导入历史无法推算，后续首次公开才计入。两张历史表只能经受控函数读取/写入，客户端不能指定日期、签号或其他人的账号。
6. 签到弹窗支持键盘操作和 Esc 关闭；手机保留右侧竖排入口，深浅主题同步适配。接口失败显示重试提示，不显示虚构的 0 天。返回首页或重新聚焦页面会刷新统计。

`node scripts/check-fortune-cloud.mjs` 匿名检查花园接口已停用、访客发布天数和表权限，不执行真实签到或修改笔记。本地数据库测试覆盖真实迁移、历史回填、重复发布、UTC+8 日期边界、账号隔离及清理后数据保留；浏览器使用模拟服务验证交互与跨设备结果复用。

## 本地运行

复制 `.env.example` 为 `.env.local`，填写本项目的 Project URL 与 Publishable key。

```powershell
npm install
npm run dev
```

只使用 Publishable key，不能把 Secret key 或 service_role 放进前端。`VITE_` 变量会出现在浏览器构建产物中；数据权限依靠数据库规则。

```powershell
npm run lint
npm test
npm run test:browser
npm run build
```

- 数据库测试中的 Auth、Storage 元数据和登录上下文在本地构造，不代表 Supabase Storage HTTP 服务也已经真实验证。
- 浏览器检查覆盖公开阅读与封面、公开确认与撤回、分享链接、重复公开请求、其他账号边界，以及登录返回、过期会话、跨标签页退出、草稿保留、206 条记录分批导出、ZIP 封面内容、取消与失败、Markdown 安全显示及字体请求大小。

- 受邀作者公开测试执行四份真实 SQL，覆盖新兑换成员发布、版本与重试、跨账号隔离、昵称授权、匿名正文/标签/封面读取及撤回。浏览器测试验证多人来源显示、手机长昵称换行、昵称纯文本渲染和账号页重试；模拟账号不代表真实云端用户已完成验证。

## 账号、备份与 Markdown 的使用

- 首页右上角和记录页面右上角可进入“我的账号”；退出使用 Supabase 的 `scope: 'local'`，其他设备继续保持登录。
- “记录管理 → 数据备份”或账号页的备份链接进入导出。选择 JSON 或 ZIP，点击“生成备份”，完成后再点击“下载备份”。
- JSON 包含记录文字、标签、创建和更新时间、版本、封面云端路径、公开状态与回收站状态。ZIP 另含 `covers/` 和 `README.txt`，每条记录的 `cover_file` 指向 ZIP 内封面。
- 单次备份最多 50 MB。读取记录或封面失败时显示错误，不把不完整 ZIP 作为成功备份提供下载。
- 导出不包含登录凭证、本机未保存草稿或 Markdown 引用的外部图片。当前提供导出和本地解压查看，尚无自动导入入口。
- 备份读取多页记录，不是数据库事务快照；导出期间请避免在其他设备批量增删改记录。
- 编辑器点击“预览”查看排版，点击“写作”继续修改；“写作说明”在新标签页打开，保留当前编辑内容。
- Markdown 原文仍保存在原有 `content` 字段，已有记录保留原文。原始 HTML 不执行，危险 URL 使用渲染器默认规则过滤；未知代码语言以普通代码显示。
- 账号和正文排版沿用原有数据。公开功能和备份中的公开状态需要先执行 `20261016_public_showcase.sql`。

## 重建首页字体

字形来自仓库内原始霞鹜文楷。子集内部字体名改为 `Portfolio Hero`，版权和 OFL 许可保留在字体元数据及 `public/fonts/OFL.txt` 中。正文继续使用系统字体。

修改首页文案时，编辑 `src/lib/heroText.js`，再生成字体：

```powershell
python -m pip install --target .tools/fonttools fonttools==4.67.0 brotli==1.2.0
python scripts/build-font.py
npm run build
```

脚本覆盖全部首页主视觉文案及可打印 ASCII，检查字形是否齐全。生成的 `src/assets/fonts/portfolio-hero.woff2` 需要随源码提交，Netlify 构建无需安装 Python。Vite 为字体生成内容哈希文件名，沿用 `/assets/` 缓存规则。

实现参考：[fontTools 字体裁剪](https://fonttools.readthedocs.io/en/stable/subset/)、[Supabase 当前设备退出](https://supabase.com/docs/reference/javascript/auth-signout)、[私有存储桶权限](https://supabase.com/docs/guides/storage/buckets/fundamentals)、[受权限检查的文件下载](https://supabase.com/docs/reference/javascript/storage-from-download)、[数据库函数与权限](https://supabase.com/docs/guides/database/functions)、[react-markdown 安全说明](https://github.com/remarkjs/react-markdown#security)、[fflate ZIP 文档](https://github.com/101arrowz/fflate)。

## 发布

先执行云端升级并本地验证，再提交源码：

```powershell
git add src supabase tests scripts package.json package-lock.json playwright.config.js netlify.toml index.html .gitignore README.md .env.example
git commit -m "完善记录管理、搜索分页、封面和草稿"
git push
```

Netlify 已通过 `netlify.toml` 固定 `npm run build` 和 `dist`，带内容哈希的 `/assets/` 文件使用长缓存。控制台仍需设置：

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

环境变量变化后需要重新构建。当前使用查询参数路由，无需为详情页添加路径重写。

## 已知边界

- 待清理图片队列保存在当前浏览器；清除浏览器数据后，未完成的清理队列也会丢失。数据库不会因此丢记录。
- 回收站保留图片便于恢复，仍会占存储额度；彻底删除成功后才尝试清理。
- 保存操作回执目前保留在数据库，便于断网重试；长期大量使用后应制定保留期和清理任务。
- 查询分页不提供跨设备实时订阅；另一设备新增后，刷新列表查看。
- 云端升级 SQL 需要在 Supabase 控制台执行；推送 `main` 后，Netlify 自动构建并发布。发布结果应通过线上页面和构建资源确认。
